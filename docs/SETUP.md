# Подготовка GREEN-API Telegram и проверка реального диалога

Приложение отправляет и получает текстовые сообщения через **GREEN-API Telegram** от имени подключённого пользовательского аккаунта. Для проверки нужны два Telegram аккаунта: **A** подключается к инстансу GREEN-API, **B** становится собеседником. Токен бота из BotFather в этой форме не используется. [Официальный порядок подключения](https://green-api.com/telegram/docs/before-start/).

## 1. Создать и авторизовать инстанс

1. Войдите или зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com/). Подтвердите регистрацию кодом из письма, если это требуется.
2. Нажмите **«Создать инстанс»** и выберите вариант для **Telegram** и подходящий тариф. Доступные тарифы и условия смотрите в кабинете. После создания дождитесь готовности инстанса.
3. Откройте созданный инстанс и нажмите **«Получить QR»**.
4. На телефоне, где открыт аккаунт **A**, перейдите в Telegram: **Настройки → Устройства → Подключить устройство**. Отсканируйте QR из кабинета. На Android настройки могут открываться через меню **☰**.
5. Если включён пароль двухэтапной аутентификации, завершите подтверждение по подсказкам GREEN-API. Пароль и код Telegram не нужно вводить в форму этого проекта; она предназначена только для параметров доступа к инстансу. Для отдельного завершения парольной авторизации предусмотрен [SendAuthorizationPassword](https://green-api.com/telegram/docs/api/account/SendAuthorizationPassword/).
6. Убедитесь, что инстанс авторизован. Приложение допускает подключение при `stateInstance: "authorized"`; `starting`, `notAuthorized` и `pendingPassword` требуют завершения подготовки. [GetStateInstance](https://green-api.com/telegram/docs/api/account/GetStateInstance/).

QR — рекомендуемый в документации способ авторизации. Подробная инструкция: [«Перед началом работы»](https://green-api.com/telegram/docs/before-start/).

## 2. Включить получение сообщений через HTTP API

В кабинете выберите инстанс, нажмите **«Изменить»** и установите параметры:

| Параметр          | Значение             | Назначение                            |
| ----------------- | -------------------- | ------------------------------------- |
| `webhookUrl`      | пустая строка        | Получать уведомления опросом HTTP API |
| `incomingWebhook` | `yes`                | Получать входящие сообщения           |
| `outgoingWebhook` | `yes`, рекомендуется | Получать статусы доставки и прочтения |

Сохраните изменения. При настройке методом API значения `yes` — строки, а не логические `true`. [Настройка HTTP API в кабинете и через API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/).

Минимальные обязательные настройки — пустой `webhookUrl` и `incomingWebhook: "yes"`. Приложение проверяет их при входе. `outgoingWebhook` нужен для обновления успешных статусов, но не для самого обмена текстом. Уведомления об ошибках отправки могут приходить независимо от этого переключателя. [Настройки инстанса](https://green-api.com/telegram/docs/api/account/GetSettings/), [статусы сообщений](https://green-api.com/telegram/docs/api/receiving/notifications-format/statuses/OutgoingMessageStatus/).

Изменение настроек через `SetSettings` перезапускает инстанс; применение может занять до **5 минут**. После очистки `webhookUrl` получение уведомлений иногда становится доступно примерно через минуту. Дождитесь `authorized` и подключитесь снова. [SetSettings](https://green-api.com/telegram/docs/api/account/SetSettings/), [ошибки ReceiveNotification](https://green-api.com/telegram/docs/api/receiving/technology-http-api/ReceiveNotification/).

## 3. Получить параметры доступа и открыть приложение

В карточке инстанса скопируйте `idInstance`, `apiTokenInstance` и `apiUrl`. Для текстового чата `mediaUrl` не требуется. Инстанс должен относиться к Telegram: его `getSettings` возвращает `typeInstance: "telegram"`. [GetSettings](https://green-api.com/telegram/docs/api/account/GetSettings/).

Для локального запуска установите Node.js **24 LTS (не ниже 24.15) или 26+** и выполните в корне проекта:

```sh
npm ci
npm run dev
```

Откройте адрес, указанный Vite в терминале, обычно `http://127.0.0.1:5173`.

1. На экране **«Войти в чат»** введите `idInstance` и `apiTokenInstance`.
2. Раскройте **«Настроить API URL»** и укажите точный `apiUrl` из кабинета, если он отличается от предложенного. Вставьте адрес хоста, без пути метода и без токена. Telegram использует путь `/waInstance…`; добавлять `/v3` или `/v4` не нужно. [Формат запросов Telegram](https://green-api.com/telegram/docs/request-format/).
3. Нажмите **«Подключить Telegram»**.

Ключ вводится через интерфейс и хранится в памяти страницы. Не добавляйте его в исходники, `.env`, Git, скриншоты или материалы для отправки работодателю. После обновления страницы понадобится повторный вход.

## 4. Проверить отправку и получение

Для однозначной проверки используйте аккаунт **B**, чей номер доступен для поиска аккаунтом **A**. GREEN-API определяет Telegram `chatId` через `checkAccount`. Ответ `exist: false` означает как отсутствие аккаунта, так и скрытый настройками приватности номер. Если известный аккаунт не находится, проверьте настройки приватности поиска по номеру у собеседника и доступность номера для аккаунта A. Не повторяйте поиск многократно: Telegram ограничивает такие запросы. [CheckAccount](https://green-api.com/telegram/docs/api/service/CheckAccount/).

1. В приложении нажмите **«Новый чат»**. В поле **«Номер получателя»** введите номер аккаунта **B** в международном формате с кодом страны и нажмите **«Создать чат»**.
2. Отправьте текст `Проверка 1: сообщение из веб-чата`. **Enter** отправляет, **Shift+Enter** добавляет новую строку.
3. На телефоне или в официальном Telegram клиента **B** убедитесь, что сообщение пришло **от аккаунта A**, и прочитайте его.
4. От имени **B** ответьте `Проверка 2: ответ из Telegram`. Оставьте веб-приложение открытым и дождитесь входящего сообщения в том же чате.
5. Повторите обмен с многострочным текстом и текстом, содержащим ссылку. Убедитесь, что содержание сохранено и каждое сообщение отображается один раз.
6. Если включён `outgoingWebhook`, проверьте обновление исходящего статуса по мере доставки и прочтения. **«Принято GREEN-API»** подтверждает приём запроса сервисом; фактическую доставку проверяйте на аккаунте B. [SendMessage](https://green-api.com/telegram/docs/api/sending/SendMessage/), [статусы исходящих сообщений](https://green-api.com/telegram/docs/api/receiving/notifications-format/statuses/OutgoingMessageStatus/).

Проверяйте при одной открытой вкладке приложения и без другого клиента, читающего очередь уведомлений этого же инстанса: полученные и подтверждённые события удаляются из общей очереди. Приложение показывает сообщения текущей сессии; загрузка прежней истории не входит в этот сценарий. [ReceiveNotification → DeleteNotification](https://green-api.com/telegram/docs/api/receiving/technology-http-api/).

## Если проверка не проходит

| Что происходит                                        | Что проверить                                                                                                                                                    |
| ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Не удаётся подключиться                               | Параметры нужного Telegram инстанса, точный API URL, состояние `authorized` и настройки получения из раздела 2                                                   |
| Известный номер не найден                             | Международный формат и доступность поиска по номеру согласно приватности аккаунта B                                                                              |
| Ответ виден в Telegram, но отсутствует в веб-чате     | `incomingWebhook: "yes"`, пустой `webhookUrl`, завершение применения настроек; другой потребитель очереди                                                        |
| Есть статус «Принято GREEN-API», но сообщения нет у B | Поздний статус отправки и состояние инстанса; принятие запроса ещё не подтверждает доставку                                                                      |
| Показан лимит запросов                                | Сделайте паузу, указанную сервисом; не повторяйте поиск номера подряд. [Ограничения CheckAccount](https://green-api.com/telegram/docs/api/service/CheckAccount/) |
| Показано «Отправка не подтверждена» после сбоя сети   | Сначала проверьте диалог в Telegram: сервис мог принять сообщение до потери ответа. Повторная отправка может создать второй экземпляр                            |

Кнопка **«Посмотреть демо без подключения»** позволяет оценить интерфейс на локальных данных. Для проверки GREEN-API выполните обмен между аккаунтами A и B по шагам выше.
